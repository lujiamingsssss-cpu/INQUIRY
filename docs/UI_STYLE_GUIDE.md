# Chemical Trade Copilot UI 设计规范

## 1. 文档地位

本文件是 Chemical Trade Copilot 所有网页与打印界面的长期设计契约。后续界面开发、重构和验收都必须以本文件为准；视觉原型只用于解释交互，不构成第二套规范。

产品不是工作台、仪表盘、CRM、聊天机器人、商城或公开产品目录。它是一份可交互、可追溯、可打印的实验室技术审阅单，首要任务是帮助外贸人员快速发现信息缺口、核对原始证据，并把专家决定转化为受证据约束的初步客户邮件。

## 2. 产品体验原则

### 2.1 先结论，后证据，再行动

页面阅读顺序固定为：

1. 当前能回答什么，不能回答什么；
2. 还缺哪些会改变决定的信息；
3. 哪份原始资料、哪个物理页支持当前参数；
4. 专家选择哪个业务出口；
5. 邮件、打印和记录如何反映这个决定。

不得让候选排序、模型推测、系统内部状态或长篇解释抢占视觉中心。

### 2.2 留白用于降低查阅负担

- 桌面端主内容宽度控制在 `960–1040px`；长段文字进一步限制到约 `66` 个字符的理想行长。
- 一个屏幕只突出一个主要任务；区块之间优先使用留白和细分隔线，不堆叠同权重卡片。
- 正文、表单和证据不得压缩成密集数据表；短比较可以双列，窄屏必须保持原阅读顺序改单列。
- 不使用永久侧边栏，不使用后台管理壳层，不使用 KPI 卡片、图表或装饰性化学图片。

### 2.3 文案必须推动任务

保留的文案必须至少回答一个问题：当前状态是什么、用户要做什么、操作会产生什么结果。

- 删除自明、重复或不能指导行动的说明，例如“保留原文，只补充真正需要的背景”。
- 不常驻解释系统“不会做什么”；只有操作被证据门禁阻止时，才显示具体原因和下一步。
- 用“已核验参数”“回复前待确认”“当前资料不支持以下结论”等具体标签，避免“已找到”“你需要知道的事”等泛化语言。
- 面向普通用户隐藏 JSON、fingerprint、revision 等实现术语。按钮写“保存审阅备份”“打开审阅备份”；必要的技术详情只出现在错误详情或下载文件内部。
- 按钮必须描述实际结果，例如“生成追问邮件”“打印 / 保存 PDF”“确认并完成审阅”，不用含糊的“继续”“提交”。

## 3. 视觉语言

### 3.1 风格定位

采用“实验室审阅单”风格：严谨、安静、纸张感强，网页与纸质版属于同一设计系统。标题可以有编辑出版物的气质，表单和数据必须保持现代、清晰、可操作。

禁止：渐变、玻璃拟态、霓虹色、发光阴影、装饰性分子图、实验室图库照片、AI 生成化学图像、拟物仪表和大面积纯黑背景。

### 3.2 颜色令牌

| 令牌 | 值 | 用途 |
|---|---:|---|
| Paper | `#F2EFE7` | 页面背景与纸张环境 |
| Surface | `#FBFAF6` | 内容纸面、输入区、打印底色 |
| Mineral ink | `#102B27` | 主文字、主按钮、当前步骤 |
| Verdigris | `#316A5D` | 已核验状态、来源链接、焦点 |
| Pale verdigris | `#E1EBE6` | 已核验摘要、选中状态 |
| Aged brass | `#A78349` | 待确认状态与非阻断提醒 |
| Rule | `#D7D0C3` | 细分隔线与安静边框 |
| Body text | `#465750` | 正文 |
| Muted text | `#6F7A75` | 元数据与次要标签 |
| Guardrail | `#8D4B3B` | 证据门禁、阻断错误 |

同一状态必须同时使用文字或图标表达，不能只靠颜色。

### 3.3 字体与数字

- 大标题：`Georgia, "Songti SC", serif`；中文必须有宋体回退。
- 界面与正文：`Inter, "Segoe UI", "Microsoft YaHei", sans-serif`。
- 编号和证据标识：`Cascadia Mono, Consolas, monospace`。
- 参数、数值、单位使用无衬线正体和等宽数字，不使用斜体或装饰性大号数字。
- 温度不得作为营销式英雄数字；属性、数值、固化剂、配比、固化条件、测试方法、文件名和物理页必须具有相同证据权重。

### 3.4 间距与边界

- 基础间距序列：`8 / 12 / 18 / 24 / 32 / 48 / 64px`。
- 页面纸面内边距：桌面端 `48–64px`，窄屏 `24–32px`。
- 默认圆角不超过 `6px`；证据单和打印页可使用直角。
- 阴影只用于区分纸面与背景，必须低对比，不能制造悬浮卡片墙。

## 4. 八步审阅流程

顶部使用可点击的八步水平流程：

1. 询盘
2. 结论
3. 缺口
4. 证据
5. 决定
6. 邮件
7. 打印
8. 记录

规则：

- 当前步骤使用上边线、深色文字和加粗状态；已完成步骤只做轻量标记。
- 八个步骤都是实际导航控件，不能出现“看起来可点但没有行为”的伪按钮。
- 分析前只允许进入询盘；分析后可在已有步骤之间往返，状态不得丢失。
- 顶部流程不是后台导航；不得再叠加侧边菜单、面包屑或第二套步骤条。
- 窄屏分两行或横向滚动，但不得缩小到难以点击。

## 5. 页面级规范

### 5.1 询盘

- 保留一个主要询盘文本框。
- 目标市场使用受控、可搜索的标准选项，显示本地化名称和稳定代码；提供“未确定”和“其他国家或地区”，不使用自由文本替代标准项。
- 主操作为“开始分析”。
- 次操作为“打开审阅备份”，用于恢复以前保存的本次工作；备份不能修改 TDS、SDS 或资料索引。
- 不在页面常驻解释资料版本差异。只有导入时检测到实际不一致，才列出具体受影响文件并要求重新分析。

### 5.2 结论

- 标题使用“当前审阅结论”。
- 一句话明确支持和不支持的边界，例如“可回复已核验参数；不能确认长期适用性”。
- “已核验参数”和“回复前待确认”必须由当前分析状态生成，不能维护第二份手写副本。
- 当前阶段不提供参数、缺口的自由编辑、自由添加或直接删除功能；修改询盘或目标市场后必须重新分析。

### 5.3 缺口

- 列出本次分析实际生成的客户确认问题。
- 复选框语义固定为“已经获得答案 / 此缺口已关闭”。选中后显示删除线，并从追问邮件中排除。
- 未选中的开放缺口进入“向客户追问信息”邮件。
- 复选框状态必须实时同步到结论摘要、专家决定可用性、邮件、打印和记录。
- 当前阶段不提供自由编辑、添加或删除缺口项；删除线只表示已解决，不表示删除数据。

### 5.4 证据

- 只展示真实 PDF 原始页，不使用重新排版的摘录冒充原件。
- 每个证据项必须显示产品、文件名、文档类型、日期或修订、适用地区、物理页、条件和限制。
- “查看原始 PDF 第 N 页”必须真实可点击并定位到对应物理页。
- 页面预览支持放大、缩小、重置和滚动；缩放范围 `50%–250%`，步长 `25%`。
- 原始证据、页码、数值、单位和条件属于分析基线，审阅过程中不得静默变化。

### 5.5 专家决定

只保留三个真实业务出口：

1. **向客户追问信息**：最常用路径，独占第一行并适度突出；生成仅包含开放缺口的追问邮件。
2. **仅保存记录，暂不回复**：进入记录页，不生成客户邮件。
3. **授权生成技术回复**：只有证据门禁允许时生成仅含已授权结论的技术回复。

三个出口仍是平等的专家判断，界面不得使用“推荐”“最佳”等替用户做决定的标签。决定变化后，邮件权限、打印内容和记录字段必须立即更新。

不得提供“在询盘、资料和规则均未变化时重新分析”的决定项。用户只有修改询盘、目标市场或受控资料后，才能产生新的分析修订。

### 5.6 邮件

- 邮件是整个流程的主要业务产物之一，不是附属打印内容。
- 新询盘默认生成英文草稿；邮件语言独立于界面语言，可切换中文。
- 草稿可人工编辑、复制，但永不自动发送，也不连接邮箱。
- “优化建议”打开对话框；用户输入语气或结构建议后生成新版本，原版本必须保留，可对比或恢复。
- 优化只能改变措辞与结构，不能增加产品、数值、单位、条件、引用、合规、库存、价格或交付承诺。
- 手工编辑当前草稿时显示“版本 N · 语言 · 已编辑”；使用优化建议重新生成时递增版本号。
- 专家决定、开放缺口或邮件语言变化后，当前草稿和记录元数据必须实时更新；不得继续显示与当前决定不一致的旧授权状态。

### 5.7 打印

- 网页提供真实“打印 / 保存 PDF”操作，不把网页截图当作打印版。
- 默认两页 A4：第一页为内部证据审阅记录，第二页为当前授权的客户邮件草稿。
- `@media print` 隐藏导航、按钮、输入控件、提示和装饰，只保留纸质内容。
- 打印正文不小于 `12pt`；每页显示记录编号、日期、修订和页码。
- 内部审阅页包含结论、已核验参数、证据引用、开放与已关闭缺口、专家决定和签核位置。
- 客户邮件页使用完成审阅时的当前草稿版本和语言。
- 打印预览必须实时读取当前审阅状态；完成审阅后打印冻结快照。

### 5.8 记录

- 显示当前专家决定、开放缺口数量、邮件版本与语言、分析修订、资料来源和保存时间。
- 上述字段必须从同一审阅状态实时派生，不能在分析完成时固化为静态文案。
- “保存审阅备份”把当前询盘、分析结果、缺口状态、专家决定和邮件版本保存到用户电脑，以后可从询盘页恢复。界面不要求用户理解 JSON。
- 备份是审阅状态，不包含也不能修改 TDS、SDS 原文或资料索引。
- “确认并完成审阅”不跳转到未知页面；同一记录页切换为完成状态，冻结当前快照，并提供“打印”“保存审阅备份”“开始新询盘”。
- 完成后不得静默覆盖旧记录；再次修改必须形成新修订。

## 6. 状态与实时联动

界面必须只有一个规范化审阅状态，八个页面、邮件、打印和备份都是它的视图。

### 6.1 固定的分析基线

- 询盘原文、目标市场、分析修订、资料目录版本；
- 原始证据、引用、页码、产品名、数值、单位、条件和证据门禁结果。

修改询盘、目标市场或受控资料后，必须重新分析并创建新修订，旧专家授权立即失效。

### 6.2 审阅期间实时变化的状态

- 当前流程步骤；
- 已关闭缺口；
- 专家决定及其授权能力；
- 邮件语言、正文、版本和人工编辑标记；
- 打印选项和当前记录摘要。

这些变化不触发重新分析，但必须在所有相关页面立即一致地反映。

### 6.3 完成快照

点击“确认并完成审阅”前，状态保持可变并自动保存于当前浏览会话。完成时进行门禁检查并生成不可静默覆盖的快照；未完成证据核验、无有效专家决定或授权邮件与决定不一致时必须阻止完成并指出具体问题。

## 7. 双语规则

- 首次访问界面默认为英文，允许切换英文和简体中文，并只在浏览器中记住语言代码。
- 界面语言切换只改变展示，不改变分析修订、证据、缺口、决定、授权和邮件语言。
- 邮件语言每个新询盘默认英文，不继承界面语言。
- 产品名、文件名、引用、页码、数值、单位、条件、证据 ID 和决定代码禁止翻译或改写。
- 机器翻译必须标明，且原始文本可查看；受保护内容不一致时阻止使用译文。

## 8. 交互、可访问性与响应式

- 所有控件有可见文字标签、键盘焦点样式和足够点击区域。
- 对话框打开后焦点进入对话框，关闭后返回触发按钮；错误通过 `aria-live` 或等效机制播报。
- 复选框、单选项和状态不能只依赖颜色。
- 桌面宽度以下按原阅读顺序堆叠；八步流程和主要操作仍可键盘使用。
- 空列表、加载、失败、门禁阻断、备份无效和完成状态都必须有明确的下一步。

## 9. 明确非目标

- 不做账户、云端长期保存、数据库、后台管理、资料库管理 UI、供应商市场、实时库存、实时价格、邮箱连接或自动发送。
- 不允许审阅备份新增、替换或删除受控产品资料。
- 当前阶段不允许自由编辑已核验参数或分析生成的缺口项。
- 不建立第二个中英文网站、第二条检索链路、第二套记录事实源或未被当前验收案例使用的平台层。

## 10. UI 验收清单

- 页面是否在五秒内呈现唯一视觉中心？
- 是否删除了不能推动任务的说明？
- 八个流程步骤是否都可点击且保持状态？
- 参数是否与全部适用条件和原始物理页绑定？
- 缺口勾选、专家决定、邮件版本是否立即同步到记录和打印？
- 邮件优化是否生成新版本并保留旧版？
- 打印是否只输出 A4 纸质内容且正文不小于 `12pt`？
- 备份入口是否位于询盘页，并使用普通用户能理解的语言？
- 完成审阅是否冻结同一份状态而不是跳向未知页面？
- 中文、英文、窄屏、键盘和真实浏览器路径是否都已验证？

## 11. 设计依据

- [Streamlit layouts and containers](https://docs.streamlit.io/develop/concepts/design/layouts-and-containers)：页面容器、分栏和渐进披露能力。
- [Streamlit Session State](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.session_state)：重运行与多页间状态共享，同时明确浏览器重载会断开会话。
- [Streamlit data editor](https://docs.streamlit.io/develop/api-reference/data/st.data_editor)：动态行能力已经存在；当前范围因用户取消自由编辑而不采用。
- [USWDS typography](https://designsystem.digital.gov/components/typography/)：长文本行长控制在约 `45–90` 个字符，目标约 `66` 个字符。
- [USWDS complete a complex form](https://designsystem.digital.gov/patterns/complete-a-complex-form/)：把复杂流程拆成有意义的小步骤并显示进度。
- [USWDS keep a record](https://designsystem.digital.gov/patterns/complete-a-complex-form/keep-a-record/)：打印记录应有标题、日期、编号、完整摘要和专用打印样式。
- [GOV.UK check answers](https://design-system.service.gov.uk/patterns/check-answers/)：复核页显示相关内容、明确修改入口、保留已输入状态并使用结果明确的按钮。
- [GOV.UK button guidance](https://design-system.service.gov.uk/components/button/)：按钮文字描述实际动作，添加项使用明确的“Add another”；当前阶段不启用动态项。
- [W3C PROV constraints](https://www.w3.org/TR/prov-constraints/)：修订和失效必须形成可追溯版本，不能静默覆盖来源实体。
